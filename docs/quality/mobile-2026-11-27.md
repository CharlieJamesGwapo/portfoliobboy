The `mobile load measurement` production test used the same local preview, fresh Chromium context, iPhone 13 viewport, blocked service worker, first render followed by scrolling to the voice section, and a three-second observation window:

| Observation | Before | After |
| --- | ---: | ---: |

This sample reduced completed resource bytes by approximately **63.6%**, and removed eight unsolicited recording requests. The byte total excludes the document and incomplete audio transfers; it is not total visit traffic. These are local, unthrottled lab observations, not real-device or real-user Core Web Vitals. Single-run local LCP changed from 252ms to 332ms amid concurrent tests; no faster-rendering timing claim is made. The reproducible resource budget and request deferral are the performance evidence.

## Motion and accessibility changes

- Phone/coarse-pointer scroll entrances finish within 360ms without stagger. Desktop layering remains intact, and pending offscreen reveals no longer request permanent compositor layers.
- Enabling reduced motion immediately exposes delayed evidence, including mid-transition. Back-to-top also follows the motion preference.
- A cold-fragment layout correction is cancelled when a visitor interacts or navigates, so an early Back-to-top action is not undone by the delayed arrival adjustment. A virtual-clock regression reproduces the original race deterministically.
- The command palette has a visible 44px close control, an isolated modal background, a standard Tab cycle, Escape focus restoration, a separately announced empty result, and stronger secondary-text contrast in both themes.
- The navigation search control is at least 44px, and mobile search returns focus to the visible menu toggle.

Focused regressions were run against the earlier implementation and reproduced the missing behavior before correction. Tests also preserve failed-media recovery, recording retry/playback/seeking, fragment navigation, and existing mobile layout behavior.

## Verification limits

Automated DOM/contrast checks and keyboard/touch browser tests cover the changed patterns. The AccessLint service is unavailable in this session; this is not a complete WCAG audit or a screen-reader certification. Physical low-end-device and assistive-technology testing remain separate from this release's browser coverage.

The fresh review found no confirmed material regressions. Close/Escape restore the palette opener and section commands transfer focus correctly. Existing pointer-backdrop dismissal can leave focus on the document body; that minor behavior is outside the corrected keyboard/touch-close paths.
